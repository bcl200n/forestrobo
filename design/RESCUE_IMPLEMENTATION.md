# 应急救援具身智能：本次实现与运行

本次交付是本机可运行的研发原型：场景与机型匹配、精细结构检查、机械臂运动学/静态载荷检查、人机协同状态机，以及新启动的多地图任务级强化学习实验。没有连接真实机器人。

## 场景匹配与机械臂

`robotics/rescue_selection.py` 将六种任务情况映射到现有设计：

|任务情况|结果|机械臂与工具|
|---|---|---|
|地震通路/缝隙侦察|E-S 概念配置|四轴轻臂 + 可部署探头|
|地震轻型清障|E-C 概念配置|五轴作业臂 + 柔顺夹爪|
|受控轻型切割|E-C 附条件配置|五轴作业臂 + 往复切割头|
|楼梯/坍塌通道|通过性未验证|不作为自主通行准入依据|
|易燃易爆区域|不匹配|没有防爆验证|
|涉水/水下|不匹配|没有密封、涉水深度和水下定位验证|

网页复用 `platforms.json` 的连杆、质量、载荷、关节力矩目标；`scripts/build_rescue_assets.py` 生成离线选型数据。
工具质量计入末端总载荷，不把标称载荷全部算作可夹持物质量。
任意输入目标的位置 IK 与静态力矩计算复用 `robotics/manipulator.py`，展示真实求解的关节角、残差、TCP 与力矩使用率。
三维网格用于固定装配结构检查；运动学线框用于本次求解结果，两者没有伪装成同一个可执行动画。

机械臂参数仍是设计目标，尚无完整采购 BOM。4/5 轴结构不能保证任意六维工具姿态；当前 IK 只求位置。
碰撞、全身稳定性、切削接触动力学、结构强度和实机标定尚未完成。

## 人机协同

`robotics/rescue_workflow.py` 的实际状态流为：

`idle → autonomy → review → paused →（人工确认）→ autonomy/manual`

网页可以注入明确标记的模拟线索，也可以导入学习策略阶段验证回放的实际候选事件；后者保留控制器、地图种子、时间步、网格位置和证据摘要。
操作员与复核人员有分开的记录名称，但这只是本地演示审计标签，没有身份认证或远程多用户调度。
当前训练与协同通过回放候选事件对接，不是实时机器人控制闭环。训练环境的短暂通信失效由规则保持，恢复后可继续搜索；协同演示里的断开/急停则必须人工复位，两者的控制权尚未统一接到同一实时控制器。

- 接受线索不确认生命，也不自动授权切割。
- 未完成的人工复核会阻止恢复自主搜索和工具检查。
- 失联/急停锁存；通信恢复不自动复位。人工复位后仍保持暂停。
- 工具检查调用现有联锁，检查停驻、支撑、气体、工具锁紧/ID、人员区域、结构对象与人工持续使能。
- 所有结果只是软件条件检查，没有继电器或工具执行输出。
- 事件追加保存在 `ops/rescue-events-*.jsonl`；重启服务会创建新任务，新旧日志分别保留。

## 新强化学习实验

入口：`rl/train_rescue_search.py`。环境：`rl/rescue_search_env.py`。
正式输出目录：`rl/models/rescue_search_20261106_v1`。不会覆盖旧废墟模型。

本轮配置：8 个独立进程、3 类任务地图（通道、碎块障碍、通信/传感中断）、每个工作进程 16 个地图种子池，共 128 个训练种子；目标 2,000,000 环境步。CPU PPO，策略网络 64/64。

这是 **二维配置空间中的搜索决策训练**，不是四足步态、履带动力学或机械臂控制训练。8 个环境不等于 8 种救援场景；工作进程按 3 类地图分配。

策略的 39 维观测包含模拟射线、已观察邻格/访问次数、只在已知自由空间计算的前沿指引、视线内合成线索、传感器/通信有效标志与时间。
隐藏目标坐标不进入策略观测；仿真真值只用于奖励、结束判定和事后评测。前沿指引是规则提供的先验，不应宣称策略从零学会全部规划。
奖励包含观测覆盖、跟随已知地图前沿的塑形、停驻扫描合成线索以及碰撞、时间与重复访问惩罚。
候选事件一律标记为等待人工复核；该环境没有雷达、热像识别或生命体征检测。
地图里程计/罗盘是理想值；通信丢失的停止行为由规则直接执行，不能算作强化学习学会安全停机。

地图划分：训练种子 100–227，阶段验证 5000/5001，最终测试 10000–10003。
最终测试共 3 类 × 4 个地图 = 12 回合，是有限条件测试，不能推断所有灾区的泛化能力。
基线为使用同样可观测信息的前沿搜索控制器。晋级要求最终搜索成功回合数严格优于基线、碰撞回合不增加且失联移动违规为零。
如果基线已达 12/12，本轮不能凭同分宣称算法更强；应在后续新协议中增加难度或预先定义效率比较，而不是事后修改本轮门槛。

可核对的产物：

- `protocol.json`：种子、工作进程、理想化条件、源码 SHA-256。
- `status.json`：PID、心跳、实际步数、吞吐、近期训练集指标。
- 每 32,768 步保存检查点；阶段验证在 65,536 步开始，之后每 131,072 步进行。
- `baseline.json`、`validation.json`、最终 `evaluation.json`：逐回合与汇总结果。
- `*-replay.json`：只含已观测地图、轨迹与候选事件；不是成功动画。
- `episodes.jsonl`、`train.log`、`error.log`：训练事件与运行记录。
- `final.zip`：最终策略；模型文件存在不等于验收通过。

若需要用户主动停止训练，在输出目录创建 `STOP` 文件；训练进程会保存 `stopped.zip` 并退出。
重启新实验应选新输出目录：

```powershell
E:\forestrobo\rl\.venv\Scripts\python.exe E:\forestrobo\rl\train_rescue_search.py --steps 2000000 --worlds 8 --output E:\forestrobo\rl\models\rescue_search_new
```
